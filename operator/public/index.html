Подключение и обслуживание клиентов

Smart Leads Control: настройка панели, подключение приложений и ежедневная работа.

Перед началом 1. Панель Control 2. Приложение клиента 3. Подключение к Control 4. Проверка связи Хранение и копии Обслуживание Решение проблем

Перед началом: где выполняются действия

Центральная панель Smart Leads Control

Единый реестр клиентов, отчётов, оплат и обслуживания. У панели собственные PostgreSQL, HTTPS-домен и ключ входа оператора.

Клиентское приложение Smart Leads

Отдельная установка для каждого клиента: приложение, PostgreSQL, файловый том и секреты. Здесь настраивают пользователей, источники, интеграции и MAX-аккаунт парсера.

Понадобятся: доступ к нужному проекту в Coolify, домены приложений, ключ входа в Control и защищённое место для хранения секретов.

Панель уже работает? Начните с шага 2. Если клиентское приложение тоже настроено — со шага 3. Повторно создавать работающие приложения и базы не требуется.

Адреса https://control.example.ru и https://client.example.ru — примеры. Используйте фактические домены панели и клиента.

ШАГ 01 · ОДИН РАЗ

Подготовьте центральную панель

Где: Coolify → проект панели Smart Leads Control → рабочее окружение, например production.

  1. Создайте PostgreSQL панели. Нажмите «+ Новый ресурс → PostgreSQL», выберите сервер и назначение панели. Оставьте сгенерированный пароль; пользователь и начальная база postgres подходят. Сохраните и запустите базу. Если она уже существует, проверьте её состояние.
  2. Скопируйте внутренний адрес базы. В PostgreSQL откройте «Общая информация → URL Postgres (внутренний)». Скопируйте URL целиком в OPERATOR_DATABASE_URL приложения панели. Не заменяйте внутреннее имя контейнера на IP сервера.
  3. Настройте сборку приложения из репозитория SMART_LEADS_CONTROL по таблице ниже.
  4. Добавьте три переменные панели. В «Environment Variables / Переменные среды» задайте значения из второй таблицы. Для каждой включите доступность во время работы контейнера (Runtime) и отключите доступность при сборке (Build time).
  5. Сохраните настройки и выполните Deploy. После запуска откройте https://ДОМЕН-ПАНЕЛИ/api/health, затем войдите на сайт с ключом OPERATOR_ADMIN_KEY. Таблицы создаются автоматически.
Важно: доступ к базе. Для PostgreSQL панели оставьте «Сопоставление портов / Ports Mappings» пустым и не включайте открытый доступ. Порт 3000 относится к приложению, внутренний порт PostgreSQL — 5432. Строка подключения содержит пароль: храните её как секрет.

Как создать случайный ключ

В терминале компьютера с Node.js выполните команду и сохраните результат в нужной переменной. Для каждого секрета запускайте команду заново.

node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"

Готово, если: проверка здоровья проходит, ключ открывает панель и доступен реестр экземпляров.

ШАГ 02 · ДЛЯ КАЖДОГО НОВОГО КЛИЕНТА

Подготовьте клиентское приложение

Где: Coolify → проект конкретного клиента → его приложение Smart Leads и PostgreSQL.

  1. Создайте отдельные приложение и PostgreSQL клиента. Используйте репозиторий клиентского Smart Leads. Проверьте наличие постоянного тома в ресурсе PostgreSQL и скопируйте внутренний URL этой базы.
  2. Подключите файловый том к приложению клиента. Откройте «Постоянное хранилище → + Добавить монтирование → Монтирование тома». Имя — например smart-leads-data; «Исходный путь» оставьте пустым; «Целевой путь» — /app/data. Добавьте том.
  3. Задайте переменные клиента из таблицы ниже. Секреты должны быть постоянными и доступны во время работы контейнера; отключите их доступность при сборке.
  4. Настройте вход администратора. Укажите ADMIN_MAX_IDS и данные MAX-бота либо ADMIN_TELEGRAM_IDS, TELEGRAM_CLIENT_ID и TELEGRAM_CLIENT_SECRET. Полная настройка входа и интеграций описана в руководстве клиентского приложения.
  5. Сохраните настройки и выполните Deploy / Redeploy клиента. Войдите в его админку, подключите MAX-аккаунт парсера через QR и добавьте нужные чаты и источники.
Если клиент уже работал без тома: до его подключения и пересоздания контейнера сохраните существующие файлы сессий и подготовьте их перенос. Новый пустой том не восстановит прежние файлы автоматически.
Переменная клиентаНазначение
DATABASE_URL, DIRECT_URLАдрес PostgreSQL этого клиента. При прямом подключении без пулера значения могут совпадать.
NEXT_PUBLIC_APP_URLПолный HTTPS-адрес клиентского приложения.
AUTH_SESSION_SECRET, CRON_SECRETРазные постоянные случайные секреты не короче 32 символов.
PARSER_PROXY_ENCRYPTION_KEY, PARSER_SESSION_ENCRYPTION_KEYОтдельные постоянные ключи шифрования не короче 32 символов. Сохраните защищённые копии.
PARSER_SESSIONS_DIR/app/data/sessions — каталог внутри тома, подключённого к /app/data.

Не меняйте ключи шифрования без переноса данных. Сохранённые сессии и настройки могут перестать читаться. Ключ подключения к Control не заменяет секреты и настройки клиента.

Готово, если: открывается сайт клиента, работает вход администратора, доступны источники и подключён MAX-аккаунт парсера.

ШАГ 03 · ДЛЯ КАЖДОГО КЛИЕНТА

Зарегистрируйте клиента и подключите отчёты

  1. В панели Control нажмите «Создать экземпляр». Заполните название, клиента, HTTPS-домен и тариф. Оплаченный период указывайте после подтверждения оплаты.
  2. Сохраните выданный блок подключения. Секрет показывается один раз. Нажмите «Скопировать обе переменные» и перенесите значения в настройки клиентского приложения.
  3. В Coolify откройте приложение этого клиента → Environment Variables → + Add. В поле Name укажите название переменной из таблицы, в Value — её значение. Добавьте обе переменные по очереди.
  4. Для каждой переменной настройте доступность: Runtime — Available in the container; Build time — недоступна при сборке; Value type — Single line. Сохраните и выполните Redeploy клиентского приложения.
ПеременнаяЗначение
SMART_LEADS_CONTROL_URLHTTPS-адрес центральной панели. Одинаков для всех клиентов этого центра.
SMART_LEADS_INSTANCE_KEYПолный ключ slk_... из карточки конкретного клиента. ID уже включён в ключ; отдельная переменная ID не нужна.
SMART_LEADS_APP_VERSIONНеобязательная метка релиза. Если не задана, передаётся версия из package.json клиента.

У каждого клиента свой ключ подключения. Не используйте здесь OPERATOR_ADMIN_KEY и не передавайте ключ входа оператора клиентам.

Карточка — запись в реестре. Её создание не создаёт сервер, контейнер, базу или домен. Эти ресурсы настраиваются в Coolify на шаге 2.

ШАГ 04 · ПОСЛЕ ПОДКЛЮЧЕНИЯ И ОБНОВЛЕНИЙ

Проверьте связь и работу клиента

  1. В Control откройте «Экземпляры», нажмите «Обновить» и дождитесь первого отчёта. Агент клиента отправляет первый отчёт примерно через 15 секунд после запуска, далее — раз в 5 минут.
  2. Откройте карточку. Проверьте время последнего отчёта, версию, время успешного сбора, очередь и ошибки.
  3. Откройте клиентский сайт и проверьте вход, источники и работу нужных интеграций.
СтатусЧто означает / действие оператора
Ожидает подключенияКлюч выдан, первого отчёта ещё нет. Проверьте переменные и запуск клиента.
На связиОтчёт получен не более 15 минут назад. Отдельно проверьте время успешного сбора.
Нет свежих данныхОтчёт старше 15 минут. Проверьте доступность клиента, связь с центром и логи мониторинга.
Ключ отозванПриём отчётов отключён. Для подключения выпустите новый ключ и обновите переменную у клиента.

«На связи» подтверждает получение отчёта. Этот статус не гарантирует исправность всех интеграций. Очередь и ошибки относятся к доставке MAX; Telegram-доставка пока не отслеживается. Недоступность Control не останавливает клиентское приложение.

Готово, если: отображается свежий отчёт, показатели проверены и клиентское приложение выполняет необходимые операции.

Хранение данных и резервные копии

Данные переживают перезапуск и замену контейнера, когда настроено постоянное хранилище. PostgreSQL хранит записи в своём томе, а клиентское приложение — файлы сессий в отдельном томе.

Что хранитсяГдеЧто проверить
Карточки, последний отчёт и журнал ControlPostgreSQL центральной панелиРесурс PostgreSQL панели → «Постоянное хранилище»: подключён постоянный том.
Ключ входа оператораOPERATOR_ADMIN_KEY в переменных панелиКлюч сохранён в Coolify и защищённом хранилище секретов.
Пользователи, права, чаты, источники, материалы и настройки клиентаPostgreSQL конкретного клиентаУ базы клиента есть свой постоянный том и резервные копии.
Первоначальные администраторы клиентаADMIN_MAX_IDS / ADMIN_TELEGRAM_IDS в переменных клиента; профили — в его PostgreSQLНастроен действующий способ входа.
MAX-сессия парсераРабочий файл в /app/data/sessions; зашифрованная копия — в PostgreSQL клиентаК приложению подключён том /app/data; сохранены ключи шифрования.

У приложения Control раздел «Постоянное хранилище» может быть пустым. Панель хранит реестр в отдельной PostgreSQL. Проверяйте том в ресурсе этой базы; добавлять файловый том самому приложению Control для хранения реестра не требуется.

Порядок резервного копирования

  1. Настройте копии PostgreSQL панели, PostgreSQL каждого клиента и клиентского тома /app/data.
  2. Храните копии вне VPS и отдельно сохраняйте секреты, необходимые для восстановления.
  3. После успешного копирования укажите в карточке дату «Последняя резервная копия».
  4. Проверьте восстановление в отдельном тестовом окружении и только после успешной проверки заполните «Проверка восстановления».

Постоянный том не заменяет резервную копию. Он сохраняет файлы при замене контейнера, но не защищает от удаления тома или потери сервера. Панель учитывает даты копирования и проверок; сами копии создаются средствами инфраструктуры.

Ежедневная работа оператора

Связь и показатели

Проверяйте экземпляры без свежих данных, время успешного сбора и ошибки доставки. При необходимости открывайте логи клиентского приложения.

Оплата

После подтверждения оплаты обновите «Оплачено по». Указанная дата включает весь день по Москве. Стоимость задаётся в рублях в месяц; автоматических списаний нет.

Пауза и архив

Это статусы учёта. Они не останавливают приложение и не удаляют данные. Работой контейнеров управляют отдельно в Coolify.

Безопасный доступ

Сессия оператора действует 8 часов. Завершайте работу кнопкой выхода. Используется общий ключ; персональные роли сотрудников пока не реализованы.

Смена ключа входа: обновите OPERATOR_ADMIN_KEY и выполните Redeploy панели — старые сессии перестанут действовать. Обычный перезапуск с прежним ключом их не сбрасывает.

Действия с карточками и ключами фиксируются в журнале. При общем ключе журнал не различает отдельных сотрудников. Не записывайте секреты в заметки карточек.

Решение типовых проблем

Ключ клиента потерян или раскрыт
  1. Откройте карточку → «Выпустить новый ключ».
  2. Сохраните выданный блок и обновите переменные клиентского приложения в Coolify.
  3. Выполните Redeploy клиента и дождитесь свежего отчёта.

Старый ключ перестаёт работать сразу. Если новый ключ не сохранён до закрытия окна, выпустите его повторно. «Отозвать ключ» отключает отчёты без выдачи замены; для восстановления связи нужен новый ключ.

После подключения нет отчёта
  1. Проверьте SMART_LEADS_CONTROL_URL и полный SMART_LEADS_INSTANCE_KEY именно в приложении нужного клиента.
  2. Проверьте доступность переменных во время работы контейнера и выполните Redeploy клиента.
  3. Проверьте DNS, HTTPS панели и её /api/health.
  4. В логах клиента найдите сообщения [МОНИТОРИНГ]. Агент запускается через npm start; в режиме npm run dev автоматически не запускается.
  5. При отозванном ключе выпустите новый и обновите настройки клиента.

Не публикуйте ключи и строки подключения в сообщениях поддержки или скриншотах.

Сборка панели: Dockerfile не найден

При ошибке open Dockerfile: no such file or directory откройте настройки сборки панели. Укажите Base Directory / и Dockerfile Location /Dockerfile.operator. Сохраните и повторите Deploy.

Карточка уже изменена в другом окне

Закройте карточку, обновите список и откройте её заново. Проверьте актуальные значения перед повторным сохранением.

После деплоя инструкция не обновилась

В настройках источника панели проверьте репозиторий SMART_LEADS_CONTROL, выбранную ветку и коммит успешного деплоя. Раздел сайта находится в operator/public/index.html; изменение только docs/operator-control.md не обновляет страницу. Выполните Deploy версии с изменённым HTML и перезагрузите страницу.
