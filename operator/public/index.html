ПАМЯТКА ОПЕРАТОРА

Настройки без пропусков

Что, куда и в какой последовательности вставлять.

01

Запустите центральный сайт Smart Leads Control

Центральный сайт — Smart Leads Control: админская панель из репозитория SMART_LEADS_CONTROL, например https://control.example.ru. Это не продаваемое клиенту приложение Smart Leads: для каждого клиента оно запускается отдельно на его VPS со своей базой, например https://client.example.ru. В Coolify откройте Проекты → SMART_LEADS_CONTROL → production. Здесь должны быть два ресурса: приложение панели и её PostgreSQL. Если приложение уже есть, повторно его не создавайте.

Нажмите + Новый ресурс → PostgreSQL, выберите тот же сервер и назначение, что у панели. Автоматическое имя ресурса оставьте как есть. Пользователь и начальная база postgres подходят; пароль оставьте сгенерированным. Поле Сопоставление портов / Ports Mappings оставьте пустым: запись 3000:5432 удалите. Порт 3000 относится к сайту; PostgreSQL доступна ему по внутреннему порту 5432. Не включайте открытый доступ. Сохраните и нажмите Start / Запустить. Если база уже создана, очистите сопоставление портов и проверьте, что она запущена.

В ресурсе PostgreSQL откройте Общая информация и скопируйте целиком URL Postgres (внутренний). Coolify уже составил его из пользователя, пароля, внутреннего имени контейнера, порта 5432 и имени базы. Вставьте этот URL в OPERATOR_DATABASE_URL приложения панели. Не заменяйте внутреннее имя на IP VPS и не публикуйте URL: он содержит пароль.

Для приложения укажите способ сборки Dockerfile, Base Directory /, Dockerfile Location /Dockerfile.operator, Ports Exposes 3000, HTTPS-домен и проверку здоровья /api/health. В Environment Variables добавьте три переменные из таблицы ниже: Runtime включён, Build выключен. Сохраните и выполните Deploy / Redeploy. Проверьте https://ВАШ-ДОМЕН/api/health и войдите на сайт с ключом администратора. Таблицы создаются автоматически.

02

Зарегистрируйте клиента

Нажмите «Создать экземпляр», заполните клиента, домен, тариф и оплаченный период. После сохранения скопируйте выданный блок переменных.

Карточка регистрирует приложение в реестре. Сам контейнер, базу и домен создайте в своём Coolify.

03

Подключите клиентское приложение Smart Leads

Откройте ресурс приложения конкретного клиента в Coolify → Environment Variables → + Add. Для первой переменной в окне New Environment Variable укажите Name SMART_LEADS_CONTROL_URL, Value — полный HTTPS-адрес панели Smart Leads Control, например https://control.example.ru. Нажмите Add Variable.

Так же добавьте вторую переменную: Name SMART_LEADS_INSTANCE_KEY, Value — ключ slk_..., выданный после создания карточки этого клиента. Не вставляйте сюда ключ администратора.

Для каждой переменной в этом же окне внизу: Build time смените с Available during build на вариант «недоступна при сборке»; Runtime оставьте Available in the container. Это два выпадающих списка, а не переключатели. Value type оставьте Single line. Сохраните переменные и выполните Redeploy клиентского приложения. Ключ у каждого клиента свой.

04

Проверьте и обслуживайте

Дождитесь «На связи» и времени первого отчёта. В карточке проверьте версию, сбор, очередь и счётчики. При отсутствии отчёта проверьте журнал процесса [МОНИТОРИНГ] в Coolify.

Отмечайте оплату, дату резервной копии и фактического тестового восстановления. Эти даты заполняются вручную.

Где сохраняются данные после перезапуска

Панель Smart Leads Control: пустой раздел «Постоянное хранилище» у приложения на вашем скриншоте — ожидаемое состояние. Карточки клиентов и журнал находятся в отдельном ресурсе PostgreSQL, для которого Coolify создаёт постоянный том автоматически. Откройте ресурс PostgreSQL → Постоянное хранилище и проверьте наличие тома. Ключ входа OPERATOR_ADMIN_KEY хранится в переменной приложения Coolify; сохраните его защищённую копию.

Каждый клиентский Smart Leads: это другое приложение со своей PostgreSQL и своим томом. Пользователи, права, чаты, источники, материалы, настройки интеграций и резервная копия MAX-сессии хранятся в PostgreSQL клиента. Рабочий файл MAX-сессии хранится в /app/data/sessions. Аккаунт для парсера подключается через QR в админке клиента, а не вводится в панель Control.

Как подключить постоянный том клиенту в Coolify

1. Откройте ресурс клиентского приложения Smart Leads, а не smart_leads_control. Сначала создайте отдельную PostgreSQL клиента и скопируйте её URL Postgres (внутренний).

2. В клиентском приложении откройте Постоянное хранилище → + Добавить монтирование → Монтирование тома. В окне со скриншота задайте Имя smart-leads-data, Исходный путь оставьте пустым (если там введено /root, удалите), Целевой путь — /app/data. Нажмите Добавить том. Coolify создаст отдельный Docker-том для этого клиента.

3. В Переменные среды этого же клиентского приложения задайте DATABASE_URL и DIRECT_URL из URL его PostgreSQL, NEXT_PUBLIC_APP_URL с HTTPS-доменом клиента, постоянные AUTH_SESSION_SECRET, CRON_SECRET, PARSER_PROXY_ENCRYPTION_KEY, PARSER_SESSION_ENCRYPTION_KEY и PARSER_SESSIONS_DIR=/app/data/sessions. Для первого входа укажите ADMIN_MAX_IDS с данными MAX-бота либо ADMIN_TELEGRAM_IDS с TELEGRAM_CLIENT_ID и TELEGRAM_CLIENT_SECRET. Не меняйте ключи шифрования после запуска без переноса старых данных.

4. Сохраните том и переменные, выполните Redeploy. В админке клиента через QR подключите MAX-аккаунт парсера и добавьте чаты/источники. В Control создайте карточку клиента и добавьте выданные SMART_LEADS_CONTROL_URL и SMART_LEADS_INSTANCE_KEY в переменные клиентского приложения.

5. Настройте резервные копии PostgreSQL панели, PostgreSQL каждого клиента и клиентского тома /app/data вне VPS. После Redeploy проверьте вход клиента, чаты и MAX-сессию. Том сохраняет файлы при замене контейнера, но сам по себе не является резервной копией.

Переменные центрального сайта

НазваниеЗначение и назначение
OPERATOR_DATABASE_URLПолный URL Postgres (внутренний) из ресурса PostgreSQL в проекте SMART_LEADS_CONTROL → production. Скопируйте его из «Общая информация».
OPERATOR_PUBLIC_URLHTTPS-адрес центрального сайта без пути, например https://control.example.ru.
OPERATOR_ADMIN_KEYСлучайный секрет не короче 32 символов. Используется для входа оператора. Смена ключа завершает старые сессии после перезапуска.

Все три переменные нужны во время работы контейнера. Генерация ключа в терминале:

node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"

Переменные клиентского приложения

НазваниеКуда вставлять / где взять
SMART_LEADS_INSTANCE_KEYВыдаётся здесь после создания карточки. Содержит ID и секрет подключения. Дополнительная переменная ID не нужна.

Ключ потерян или раскрыт

Откройте карточку → «Выпустить новый ключ». Скопируйте новый блок в Coolify клиента и выполните Redeploy. Старый ключ перестанет приниматься сразу.

«Отозвать ключ» отключает отчёты без выпуска нового. Для повторного подключения выпустите новый ключ.

Оплата и резервные копии

«Оплачено по» включает весь указанный день по Москве. Укажите дату только после подтверждённой оплаты. Стоимость задаётся в рублях в месяц.

Пауза и архив — статусы учёта. Они не выключают клиентское приложение. Резервное копирование настройте в инфраструктуре; панель хранит даты выполненных действий.

Что означают показатели

«На связи» подтверждает получение отчёта, но не исправность всех интеграций. Время успешного сбора проверяйте отдельно. «Нет свежих данных» означает, что отчёт старше 15 минут.

Объём базы измеряется в PostgreSQL. Очередь и ошибки относятся к доставке MAX. Telegram-доставка пока не отслеживается.

Доступ и обслуживание

Центральная панель имеет отдельный вход. Не передавайте ключ оператора клиентам. Сессия действует 8 часов; закрывайте её кнопкой выхода.

Действия с карточками и ключами записываются в журнал. В этой версии используется один общий доступ оператора; персональные роли сотрудников пока не реализованы.

Подробная инструкция находится в репозитории: docs/operator-control.md. Настройки Coolify: официальная документация.
